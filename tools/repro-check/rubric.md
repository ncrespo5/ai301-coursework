# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
| --- | --- | --- | --- |
| Targeted claim | Claim draft against the issue title, body, and thread. | The claim identifies the issue or the specific behavior that will be investigated and makes a bounded commitment. A project-wide or generic claim, or a guarantee of a fix or timeline that the draft cannot support, fails. In live mode, a classmate's claim does not block a PathReview claim. | required |
| Relevant environment | Repro report's environment and setup against the issue's affected versions, platform, configuration, and code state. | The report identifies the revision or release and the runtime, platform, or settings material to the bug. Any material deviation from the reported environment is named and scoped. Incidental versions that cannot affect the behavior are optional. | required |
| Followable steps | Repro report's starting state, fixtures or inputs, command or UI sequence, and trigger. | Pass if a maintainer can reconstruct the experiment without guessing a prerequisite, input, or action material to the reported behavior. An input described by its decisive properties is sufficient when instance details only affect incidental output. A precise reference to an existing recipe can supply unchanged steps. | required |
| Proof matches the issue | Test output, logs, screenshot, or concrete observed result against the issue and the reproduction steps. | A positive reproduction needs an observable result matching the reported failure. For an honest cannot-reproduce report, pass if the same operation was actually exercised, there is observable output, and the reporter identifies any suspected trigger condition their environment or input did not reach. A different operation, a setup failure that prevented the attempt, or no diagnostic result fails. | required |
| Outcome matches the evidence | Expected and observed behavior, the report's conclusion, and any limitations against its supplied artifacts. | The report distinguishes the expected behavior, the observed behavior, and the conclusion under the actual conditions. A clearly qualified hypothesis about why the outcome differed is acceptable. Representative output can support the observed result without a transcript for every run. Fail if the report conflates a hypothesis with a finding or generalizes beyond the tested conditions. | required |
| Repository conventions | Both drafts read against stated issue templates, contribution docs, and any explicit disclosure requirement in repo facts or the issue thread. | The relevant comments satisfy the repository's stated requirements, including an explicit disclosure where one is required. An absent optional heading does not matter. If the repo has no applicable stated requirement, this check passes. | required |

## Verdict rule

Accept when every applicable required check passes. Reject if an applicable required check fails or remains unclear. In live claim-only mode, grade only Targeted claim and the claim's applicable Repository conventions. Report the other checks as unclear because the reproduction draft is not yet applicable, and omit them from the verdict.
