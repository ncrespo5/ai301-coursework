# Rubric: is this a good first issue?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Bounded change | Issue body, labels, linked files, and maintainer comments on scope, design, and prior attempts. | Pass when the evidence identifies one manageable behavior to change with a focused way to verify it. Closely related files or interfaces can be part of the same change, and an exact file list is optional when the behavior and likely area are clear. A small set of similar fixes within the same feature can be one task. Fail for umbrella issues, broad rewrites, scope spanning unrelated areas, unresolved design that requires a maintainer decision, or support questions with no contribution to make. Multiple abandoned attempts on a long-open issue are a reason to fail when the thread still does not show a settled approach or an independently deliverable smaller change. | required |
| No duplicate work | Issue Development panel and comments, linked PR state and scope, and Assignees panel. | Pass after checking those sources and finding no open PR that implements the same change or other clear evidence of active ownership. Fail if there is an open PR for the same change, or a maintainer has assigned or confirmed another contributor is actively implementing it. Apply the Path Review house rule in live mode to classmates’ claim comments. A closed PR without a current owner or replacement does not by itself block the issue. | required |
| Repository open to contributions | Archived flag, maintainer notices, recorded push or release dates, default-branch commits, and the issue thread or repo-facts maintainer response sample. Evaluate dates relative to the capture date in a snapshot and today in live mode. | Fail if archived, read-only, or explicitly closed to contributions. Also fail if there is direct evidence of prolonged inactivity: all available push, release, and commit dates are older than 12 months, and the reviewed threads and response sample show no maintainer intervention within that period. Pass for an unarchived repo without a closure notice when there is evidence of a push, commit, release, or maintainer response within 12 months. A missing release record by itself is not evidence of inactivity. | required |
| Contribution policy | Contribution policy in the snapshot, or live contributor docs, AI policy, and PR template. | Pass if the published policy allows the planned workflow or the checked sources are silent. Disclosure, testing, and human-review requirements are acceptable if they can be followed. Fail if the policy explicitly rules out the planned AI-assisted workflow. | required |
| Recent activity | Last five default-branch commits and maintainer replies on the issue or in the repo-facts response sample. Use the snapshot date in eval mode and today in live mode. | Pass if there is a human-authored or human-merged commit or a maintainer reply within 90 days. Fail if the dates are known and all are older. | preferred |

## Verdict rule

Accept when every required check passes. Reject if a required check fails or remains unclear after checking its evidence. A preferred check only helps rank accepted issues. Old or unclear activity alone does not rule out a contribution.
